# 离线书库

> 状态：active ｜ 最后核对：2026-11-16 @ 7fc34ce

「搜索」页右上角的**离线书库**是当前设备已经保存的公开文章的本地目录。它不是
服务器搜索、下载管理器、收藏列表，也不是完整备份：只有首页最新列表和曾成功打开的
详情页写入的公开文章才可能在这里出现。草稿、私密账号资料和发布队列
不会进入书库。

## 能做什么

- 不登录也能打开；读取、搜索、列表、清空均不请求网络，也不做 `/health` 探测。
- 浏览当前 API 服务器和当前内容语言（`zh-CN` 或 `en`）的缓存文章；点开后仍使用普通
  阅读页。列表本身刻意不创建封面/头像图片 provider，避免把「浏览离线目录」变成图片
  网络请求。
- 搜索文章标题、作者名、标签和已缓存的可读正文。大小写不敏感，使用**子串**语义（例如
  `雨` 能找到 `下着雨`），与 no-wave 当前的搜索方向一致。空格分开的词都必须命中；双引号
  可把含空格的一段作为一个词，例如 `雨 "安静 花园"`。每次最多 8 个词、输入最多 120 个
  UTF-16 单元、单个词最多 60 个。
- 结果严格按标题、标签、作者、正文的命中字段排序；同一字段层级再按匹配精度、服务器
  更新时间、slug 决定稳定顺序。正文命中显示纯文本片段，不渲染 Markdown 或 HTML。
- 查看当前命名空间的文章数和文章文字/JSON/URL 元数据的近似字节数，并明确清空它。

## 范围与隐私

缓存 identity 是 `(backend, content_locale, slug)`。因此切换 API `API_BASE_URL` 或内容
语言会得到不同的书库，不会把旧服务器或另一语言的文章显示为当前结果。语言切换途中
完成的 SQLite 读取有 generation/locale 检查，迟到结果会被丢弃而不是绘制到新语言页面。

近似大小只相加 `blog_cache` 一行所含文本、JSON 和 URL 的 UTF-8 字节；它不包含 SQLite
页和 WAL 开销、数据库其他表或 `cached_network_image` 的图片文件，因此不能被当作设备
总用量或离线图片大小。缓存正文也可能已经过期或来自旧的压平格式；书库会说明这个限制，
不会把它说成服务器完整档案。

「清空已缓存文章」二次确认后只执行当前 backend + content locale 的
`DELETE FROM blog_cache`。它绝不会删除：

- 其它 API 服务器或其它内容语言的缓存；
- 本地草稿（含账号草稿）；
- 发布队列及其封面文件；
- 会话/安全存储、资料缓存、主题或语言设置；
- 阅读历史。

旧版、无法证明 backend 的缓存仍保留在空 backend 命名空间，也不在书库中显示或被普通
清空动作删除；此行为沿用 [SQLite 存储](sqlite-storage.md) 的迁移保护。

## 实现边界

书库不引入 FTS 表或新依赖，也没有改变 SQLite schema。每个 backend + locale 的文章缓存
已有最多 250 条的 LRU 上限，查询只扫描当前内存快照；这避免让 FTS shadow table 在每一个
缓存写入路径上出现同步风险。这个决定也与 no-wave
[ADR 0030](https://github.com/BrainEno/no-wave/blob/ba5c73b1915e74fe7a444f85f31755b1adc834af/docs/architecture/decisions/0030-body-search-generated-column.md)
对有界 SQLite 搜索的取舍一致。

清空与读取失败只显示本地存储错误，不会伪装成网络错误或清空成功。清空成功后会重新读取
同一命名空间，而不是凭空构造「空」状态，避免同时发生的正常缓存写入被 UI 隐藏。真实设备
上的 WAL/磁盘空间、图片缓存、极大正文的内存与可访问性仍需单独验收。
