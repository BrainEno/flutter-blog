# no-wave API 与 Flutter 客户端差距（2026-11-02）

本表静态核对 no-wave 默认分支快照 [`effeb9a7`](https://github.com/BrainEno/no-wave/tree/effeb9a7016278a385ecfd19d49a26eb7151c58b) 的 [`routes.ts`](https://github.com/BrainEno/no-wave/blob/effeb9a7016278a385ecfd19d49a26eb7151c58b/apps/api/src/transport/rest/routes.ts)、handler、数据校验和 Flutter main `76efc7c` 的实际调用。相对前次审计 `ea276a5e`，后端增加 latest 游标、搜索正文、会话列表/撤销并修复改密的会话语义；`596ca5ae` 到此快照仅有 CI/文档改动。网页也新增本地划线等功能，但不意味着已有服务端同步 API。源码存在不代表某个部署已升级、邮件可投递或移动端联调通过。

本表描述已合并的客户端主线；改密 [#73](https://github.com/BrainEno/flutter-blog/pull/73)、只读会话列表 [#82](https://github.com/BrainEno/flutter-blog/pull/82) 和离线 outbox [#66](https://github.com/BrainEno/flutter-blog/pull/66) 均未合并，不能当作当前功能。

## 接口与用户能力

| 能力 / API | 客户端状态 | 语义与后续 |
|---|---|---|
| 公开最新文章 `/articles`，点赞、评论、标签、作者、关注，发布、软删和恢复 | 已接入 | 延续现有实现；删除恢复后作品为服务端草稿。 |
| 最新文章 `GET /articles?cursor=…` | 首页在线 latest 已接入 | 与旧服务兼容回退 offset；密集时间窗口有上限并明确停止，无法保证完整快照。其他列表仍使用 offset；详见 [分页说明](latest-feed-cursor.md)。 |
| 文章搜索 `query` | 已接入，依赖部署 | 新后端支持标题、摘要及部分正文块文本，旧部署可能只查标题/摘要；离线只查本机缓存标题，不能保证完整结果。 |
| 内容语言 `locale` | 未完整适配 | 首页、关注、精选、搜索、作者及详情等文章请求目前固定 `zh-CN`；界面可切换英文不代表能浏览仅有 `en` / `zh-TW` 译文的作品。切换内容语言时还需隔离缓存与分页，不能简单复用现有缓存。 |
| 关注流 `GET /me/feed` | 已接入 | 仅登录用户；只含被关注作者的已发布文章，取消关注后刷新消失。无关注或无作品时返回空，不回退到公共流。每页 10 条，使用 offset；网络不可用时明确报错，不把无账号作用域的公共缓存当关注流。 |
| 精选 `GET /featured` | 已接入只读 | 登录与否均可查看，按编辑指定顺序分页，最多 20 篇；空列表不回退公共流，不使用公共缓存。编辑端 `PUT /featured` 尚未接入。旧部署没有此接口时会显示请求错误。 |
| 最多收藏 `GET /articles?sort=popular` | 已接入 | 此快照对**全部已发布作品**按累计收藏数排序；旧部署可能仍使用近 30 天窗口，API 不提供版本协商。客户端避免写死时间范围，网络不可用时不伪造排序。 |
| 账号：`PUT /me/password`、`PUT /me/email`、`GET /me` 返回邮箱/验证状态 | 未接入 | 改密需当前密码，保留当前会话、撤销其他会话；改邮箱也需当前密码，更换地址后变为未验证。客户端目前仍显示登录时的本地邮箱；#73 改密仍为未合并草稿。**错误当前密码也可能是 401**，接入时需避免将其当作 access token 过期而盲目重复提交。 |
| 登录会话 `GET /me/sessions`、`DELETE /me/sessions[/:sessionId]` | 主线未接入 | #82 是尚未合并的只读列表，不实现撤销；不提供设备名称或位置，旧无 `sid` token 可能无法识别当前会话。请求 IP 仍用于限流。 |
| 找回/重置密码、邮箱验证与重发 `auth/*`、`POST /me/email-verification` | 未接入 | 需安全的链接处理、匿名防枚举和邮件状态提示；后端邮件默认关闭，实际投递未验证。 |
| `contentBlocksVersion: 1` 富文本、结构化 v0、正文多图 | 按当前契约只读支持，编辑未支持 | 阅读与朗读共用 AST，保留标题、引用归属、列表、代码空白、图片/说明及行内样式；未配置可信 `WEB_BASE_URL` 时站点相对资源不可用。未知/损坏正文及迁移前已压平的 no-wave 缓存提示可能不完整；重获的结构化正文随文章缓存保存，图片本身不保证离线。更新前检查新鲜正文及摘要，阻止普通编辑器覆盖不兼容结构并回传摘要；仍不是富文本编辑。服务端未提供条件更新，检查不能防止随后并发修改；客户端重建块 ID，服务端可能重算空摘要。 |
| `GET /me/articles`（含服务端草稿） | 未接入 | 当前“我的文章”读公开作者列表，不能完整查看服务端草稿；恢复到草稿的作品不能依靠该列表重新发布。本机自动草稿与服务端草稿不是同一数据。 |
| 用户数据导出 | 部分实现，非完整备份 | 当前作者列表只请求最多 100 篇 `zh-CN` 已发布作品，正文压平且不保留全部图片/结构，也不含服务端草稿或其他语言。客户端界面和文档已明确提示限制；完整、可恢复导出须另行设计和验证。 |
| 通知 `GET /me/notifications`、`unread-count`、单条/全部已读 | 未接入 | 需按账号隔离、明确刷新/失败与已读语义；后端尚无移动设备令牌和推送投递，不能宣称实时推送。 |
| 私信 `conversations*` | 未接入 | 需要受信参与者鉴权、消息游标分页、已读语义、账号隔离；创建会话和发送消息需要稳定的 `Idempotency-Key`，失败/重试不能制造重复消息。 |
| 用户搜索、粉丝/关注列表 `GET /users*` | 未接入 | 可在独立社交功能中接入；关注/取关本身已存在。 |
| 分类 `categories*`、编辑角色 `PUT /users/:id/role`、分类维护 | 未接入 | 最新后端规定分类由编辑共同维护；标签仍对登录作者开放。角色和权限由服务器强制，不能只靠隐藏按钮。 |
| 媒体 `/api/media/:id` 别名 | 不需要改现有上传路径 | 客户端已由资源 id 构造版本化 `/api/v1/media/:id`；新别名主要使网站相对地址可直连 API。媒体上传仍无幂等键/删除接口，不安全地自动重试可能产生孤儿资产。站点相对头像 origin 问题另见 [#63](https://github.com/BrainEno/flutter-blog/issues/63)。 |
| 新建文章 `Idempotency-Key` | 未接入 | 服务端支持相同 key + 相同请求重放，但自动 slug 碰撞后的重放仍有 [no-wave #137](https://github.com/BrainEno/no-wave/issues/137)；客户端普通发布尚未固化跨重试 key。离线 outbox 的独立草稿 PR 仍待评审，不能声称已可靠离线发布。 |

## 验证边界与建议顺序

本次首页及正文适配的请求路径、分页、账号切换、离线和结构化阅读有客户端自动测试；真实后端、数据、图片和设备需独立验收。`latest` 仍保留现有离线缓存策略，精选、收藏榜与关注不写入也不读取这个列表缓存；通过单篇详情接口获取的文章会缓存，从卡片直接打开不会额外预缓存。旧 no-wave 缓存只保留压平后的文本，迁移不会凭空恢复原始结构。offset 翻页时服务端列表变化可能造成位移，客户端去重不能防止所有遗漏，下拉刷新可重新读取。

此轮正文适配的 SQLite v5 仅为文章缓存增添可空 JSON 列，不删除文章、草稿、偏好或阅读历史。旧 no-wave 缓存根据服务端文章 ID 标记为可能不完整，早期本地 Markdown 保留原行为；新版应用重新联网获取后写入新数据。

后续本地草稿隔离使用 SQLite v6：新草稿按后端、账号和文章隔离；未记录归属的旧 SQLite/Isar 草稿保留但不自动显示或分配。参见[旧草稿说明](unclaimed-drafts.md)。旧版应用回退打开新版数据库并未验证，降级可能再次向错误账号展示旧草稿，升级/降级前应自行备份设备数据。

后续可独立补齐富文本安全往返、账号安全、服务端草稿、通知、私信及社交列表；具体界面和邮件/推送部署能力应分别验证，不将管理接口或未实现的服务器能力伪装成客户端功能。
