# no-wave API 与 Flutter 客户端差距（2026-11-02）

本表静态核对 no-wave 默认分支快照 [`effeb9a7`](https://github.com/BrainEno/no-wave/tree/effeb9a7016278a385ecfd19d49a26eb7151c58b) 的 [`routes.ts`](https://github.com/BrainEno/no-wave/blob/effeb9a7016278a385ecfd19d49a26eb7151c58b/apps/api/src/transport/rest/routes.ts)、handler、数据校验以及 Flutter main 和表中明确标注的客户端变更；改密相关的会话语义另复核了 `7590ca98` 与 `58dc3419`。相对前次审计 `ea276a5e`，后端增加 latest 游标、搜索正文、会话列表/撤销并修复改密的会话语义；`596ca5ae` 到此快照仅有 CI/文档改动。网页也新增本地划线等功能，但不意味着已有服务端同步 API。源码存在不代表某个部署已升级、邮件可投递或移动端联调通过。

### 增量核对：评论线程 cursor

no-wave main `bbe9d198`（PR #253）现提供 `GET /articles/:slug/comments?limit=N&cursor=…`：按 `(createdAt ASC, id ASC)` 排序；每页最多 100 个顶级评论、回复树随根返回；cursor 是 `base64url("<createdAt>|<id>")`，取上一页最后一条根评论的原始毫秒时间戳和 UUID。响应仍为普通数组，短页表示到末尾，满页需要继续读直到空页；PostgreSQL 需先应用 `0031_comment_created_at_millisecond_precision.sql`。Flutter 客户端已接入按需分页，并为旧服务忽略/拒绝 cursor 增加重复页保护和停止提示。部署是否已升级未验证；实现细节见 [评论线程文档](comments.md) 与 [no-wave 契约](https://github.com/BrainEno/no-wave/blob/bbe9d198208cc9f4267e18e3a4ddcc88b2ad535a/docs/api/comment-thread-pagination.md)。

本表包含改密 [#73](https://github.com/BrainEno/flutter-blog/pull/73)、只读会话列表 [#82](https://github.com/BrainEno/flutter-blog/pull/82)、结束登录会话 与账号作用域的“我的文章”列表（含服务端草稿）；离线 outbox [#66](https://github.com/BrainEno/flutter-blog/pull/66) 已关闭，需按 #23 重做。后端已提供登录会话列表与单个/批量撤销；客户端只实现列表，不实现撤销。列表不提供设备名称或位置，旧无 `sid` token 可能无法识别当前会话；请求 IP 仍用于限流。

| 评论线程 `GET /articles/:slug/comments?limit=50&cursor=…` | 已接入 keyset 分页 | Flutter 按需读取 50 个顶级评论；回复树随根返回。cursor 由上一页最后根评论的原始 `createdAt` 与 UUID 生成；短页结束，满页继续直到空页。续页失败保留游标供重试；本地已有的根评论 ID 去重，cursor 未推进或续页无新根时停止并提示。目标部署升级与 PostgreSQL `0031` 迁移状态未验证；细节见[评论线程](comments.md)。 |
| 最新文章 `GET /articles?cursor=…` | 首页在线 latest 已接入 | 与旧服务兼容回退 offset；密集时间窗口有上限并明确停止，无法保证完整快照。其他列表仍使用 offset；详见 [分页说明](latest-feed-cursor.md)。 |
| 文章搜索 `query` | 已接入，依赖部署 | 新后端支持标题、摘要及部分正文块文本，旧部署可能只查标题/摘要；离线只查本机缓存标题，不能保证完整结果。 |
| 内容语言 `locale` | 已接入（界面语言决定内容语言） | 内容语言由界面语言推导（`ContentLocale`），首页、关注、精选、搜索、作者、分类、标签订阅等请求都带该 `locale`；离线缓存以 `(slug, content_locale)` 为键，两种语言并存（v7）。界面切语言后分页会话按 generation 丢弃旧页。仍未提供 `zh-TW` 界面：该语言的作品只能经作者的“全部语言版本”列表看到。 |
| 语言版本 `?allLocales=true`、`PUT /articles/:id` 的 `locale` | 已接入只读浏览 + 写回 | 文章 id 是一篇作品，`(id, locale)` 才是其中一版译文。“我的文章”可切到“全部语言版本”，服务器按语言各返回独立条目并在 `meta.locales` 标明读过的语言；没有该标记时（旧部署忽略参数）界面说“只能列出当前语言”，不把单语言结果说成完整档案。编辑、离线队列和回收站恢复都按文章自己的 `locale` 写回，而不是按界面当前语言——服务端省略 `locale` 视为 `zh-CN`，用错会覆盖另一版译文。每种语言最多 50 条（服务端按语言计 `limit`），没有跨语言总数，也没有“列出某篇作品的其它语言”的公开接口；`zh-TW` 只作遗留版本可见，应用没有该界面语言。详见[语言版本](article-editions.md)。 |
| 关注流 `GET /me/feed` | 已接入 | 仅登录用户；只含被关注作者的已发布文章，取消关注后刷新消失。无关注或无作品时返回空，不回退到公共流。每页 10 条，使用 offset；网络不可用时明确报错，不把无账号作用域的公共缓存当关注流。 |
| 精选 `GET /featured` | 已接入只读 | 登录与否均可查看，按编辑指定顺序分页，最多 20 篇；空列表不回退公共流，不使用公共缓存。编辑端 `PUT /featured` 尚未接入。旧部署没有此接口时会显示请求错误。 |
| 最多收藏 `GET /articles?sort=popular` | 已接入 | 此快照对**全部已发布作品**按累计收藏数排序（只数点赞、不数评论，同分按发布时间倒序）；旧部署可能仍使用近 30 天窗口，API 不提供版本协商，客户端避免写死时间范围，网络不可用时不伪造排序。这个排序**没有游标**：收藏会在读者翻页时到达，同一条作品可能被再遇到或被跳过，服务端因此只接受 offset，并把 offset 收紧到 **10000**（`latest` 是 100000）；再深就是 `400 BAD_USER_INPUT`，message 明说「改用 sort=latest 加游标」。客户端在本地就停在这个上限（不再发出只会被拒的请求），列表底部不写「没有更多」，而是说明这个榜单会在阅读时重排、并给一个「去「最新」继续」的按钮；真收到 400 时同样按「到头了」处理——重试必然还是 400，把它当普通错误只会让人反复点。`/authors/:id/articles` 的 `sort=popular` 同限（同样 10000）：作者页因此在「最新 / 最多收藏」之间切换，两个顺序各自按 offset 翻页、互不混页，每页 20 条；到界时列表底部说明原因并给「去「最新」继续」，收到 `400 BAD_USER_INPUT` 也按同一结论处理。切换顺序时在途的旧顺序页会被丢弃——它描述的是另一份列表，拼进来就成了两段不同的排序。 |
| 改密 `PUT /me/password` | 已接入登录态界面 | 先用账号围栏安全读取 `GET /me`，再使用当前密码和新密码提交一次，不对敏感 PUT 自动重试或跟随重定向。401 既可能是密码错误也可能是会话失效；超时、连接中断、5xx 或异常响应可能发生在提交后，界面提醒其他设备仍可能登录，提示先验证新密码、不要盲目重试。服务端文档称保留当前会话，但本地真实 SQLite 复现会连当前会话一起撤销（见下方和 [no-wave #129](https://github.com/BrainEno/no-wave/issues/129)），客户端提示可能需重新登录，也不把返回数解释成其他设备数。旧部署可能无该接口。 |
| 改邮箱 `PUT /me/email`、`GET /me` 的邮箱/验证状态 | 已接入登录态界面 | 同改密：先用账号围栏安全读取 `GET /me` 预检身份，再用当前密码新地址提交一次，不自动重试、不跟随重定向；401 同时覆盖密码错误与会话失效，超时/断连/5xx/异常回包报「结果未知」并提示先核对当前地址。`EMAIL_TAKEN`（409）单独提示「已被其他账户使用」，429 提示限流，404/405 说旧部署暂不支持，同地址本地识别为无需修改、不消耗一次密码校验。成功后把服务端归一化的地址写回会话存储与 `AppUserCubit`；改邮箱不撤销其他会话。`emailVerifiedAt: null` 只作提示，不做任何功能门禁，客户端也不发验证邮件。详见[账户邮箱](account-email.md)。 |
| 登录会话 `GET /me/sessions` + `DELETE /me/sessions/:sessionId` + `DELETE /me/sessions` | 已接入（列表 + 结束会话） | 针对 no-wave [`596ca5ae`](https://github.com/BrainEno/no-wave/blob/596ca5ae09f36789f85d539dc5d268fe1cb9e180/docs/architecture/decisions/0019-device-list-without-device-fingerprints.md) 的补充核对。服务器最多返回 50 项，只有创建、最近令牌刷新和过期时间，列表不包含设备名称、IP 或位置；旧 token 或列表上限可能无法标识当前会话。页面只在内存保存结果，并按账号和 session generation 失效，旧部署返回 404/405 时明确提示不可用。结束单条会话按服务端语义把 404 视为「已经结束」（目标状态达成），集合端的 404/405 视为旧部署、报「暂不支持」而不是「已全部结束」；两者都 `followRedirects: false`，不自动重试，结果不可判定时只说「结果未知，请刷新核对」。`DELETE /me/sessions/:sessionId` 对任何带 `content-length`/`transfer-encoding` 的请求直接 400，客户端测试为此锁定「不带 body 头、body 0 字节」；结束「本机」会话是允许的，但页面不提供该按钮（那等于退出登录）。批量撤销只赦免能命名自身的 token：`current` 未识别时确认框会明说可能连本机一起登出。API 源码存在不证明实际部署已升级。 |
| 邮箱验证 `POST /me/email-verification`、`POST /auth/verify-email` | 已接入登录态界面 | 「验证邮箱」页先用 `GET /me` 读 `emailVerifiedAt`，再请求发信（202，body 为空）。202 只表示受理：服务端投递失败也照常回 202，界面不承诺送达。`alreadyVerified` 会重新读状态；`MAIL_DISABLED`（409）是永久答案，明确告知「这套部署不发账户邮件」而不是「稍后重试」；429（用户 5/时、IP 20/时）不自动重试；超时/5xx 说明邮件可能已发出。邮件链接指向网页前端 `<身份服务地址>/verify-email?token=…`，应用无法接管，因此提供「在浏览器确认后刷新状态」与「粘贴链接/确认码在应用内兑换」两条路径；确认码按服务端形状（43 字符 base64url）本地校验，兑换请求不带 Bearer、不跟随重定向、不重放，401 统一表述为「无效、已使用或已过期」。`emailVerifiedAt` 只作提示，不做任何功能门禁。后端邮件默认关闭，实际投递取决于部署配置。详见[账户邮箱](account-email.md)。 |
| 找回/重置密码 `auth/forgot-password`、`auth/reset-password` | 未接入 | 需要安全的链接处理与匿名防枚举文案；后端邮件默认关闭，实际投递未验证。 |
| `contentBlocksVersion: 1` 富文本、结构化 v0、正文多图 | 按当前契约只读支持，编辑未支持 | 阅读与朗读共用 AST，保留标题、引用归属、列表、代码空白、图片/说明及行内样式；未配置可信 `WEB_BASE_URL` 时站点相对资源不可用。未知/损坏正文及迁移前已压平的 no-wave 缓存提示可能不完整；重获的结构化正文随文章缓存保存，图片本身不保证离线。更新前检查新鲜正文及摘要，阻止普通编辑器覆盖不兼容结构并回传摘要；仍不是富文本编辑。服务端未提供条件更新，检查不能防止随后并发修改；客户端重建块 ID，服务端可能重算空摘要。 |
| `GET /me/articles`（含服务端草稿） | 已接入 | “我的文章”改为账号作用域请求，按账号与当前会话围栏校验，不跟随重定向，也不写入公共文章缓存。服务器按更新时间倒序返回本人全部未删除作品（含草稿），最多 100 条；界面给草稿加标记，打开编辑器保存时按发布提交，因此恢复出来的草稿可以重新发布。结构不兼容（富文本或未知块）的草稿仍会被普通编辑器拒绝，需要到网页编辑。服务端不返回草稿与已发布的分页，超过 100 条时列表可能不完整；旧部署没有该接口时回退到公开作者列表。本机自动草稿与服务端草稿仍是两套数据，导出也不含服务端草稿。 |
| 用户数据导出 | 部分实现，非完整备份 | 当前作者列表只请求最多 100 篇 `zh-CN` 已发布作品，正文压平且不保留全部图片/结构，也不含服务端草稿或其他语言。客户端界面和文档已明确提示限制；完整、可恢复导出须另行设计和验证。 |
| 通知 `GET /me/notifications`、`unread-count`、单条/全部已读 | 已接入只读收件箱 + 菜单未读角标 | 页面进入时读一次，下拉刷新，不轮询也不推送；后端仍无移动设备令牌和推送投递。服务端现在支持 `cursor` keyset 分页；客户端按需读取旧页，空数组确认末尾，收件箱未读摘要只统计已加载页，个人中心角标仍取全量。个人中心菜单的角标另外调用 `unread-count` 取全量未读数，只在打开个人中心、账号变化和离开收件箱时读一次，失败静默保留上次的值、不落盘。每次请求带账号围栏，账号切换即丢弃旧响应。`payload` 是 JSON 字符串，`message.created` 因缺少会话页只陈述事实，`article.deleted` 用 `purgesAt` 给日期，未知事件保留为通用行；旧部署无此路由时明确提示不可用。详见[通知收件箱](notifications.md)。 |
| 私信 `conversations*` | 已接入收件箱、会话、发送、显式已读与创建者删除 | 进入页面读一次，消息按 `before` 游标向前翻页，不轮询也不推送（服务端仍无设备令牌与推送投递）。创建会话和发送消息都带稳定的 `Idempotency-Key`：同键重试由服务端重放，不会产生重复会话或重复消息；`409 IDEMPOTENCY_CONFLICT` 与普通状态冲突分开处理。会话端点对「不存在」与「非成员」同为 404，客户端原样呈现并给缺失态而非重试；非成员读消息为 403，同样呈现为无权查看，不伪造 404 语义。已读是显式动作：`PUT …/read` 无游标，服务端会把它已收到的全部消息标为已读（包括本机未加载的部分），界面在按钮旁说明这一点，且只在服务端回 `true` 时清零。会话只带 userId，名字经公开作者资料解析，一页最多 12 个并缓存 200，解析不到显示「未知读者」而不显示 UUID。收件箱无游标，只显示最近 50 个会话；参与者增删未接入。会话删除仅对创建者开放，确认后永久删除所有参与者的会话和消息；只在服务端回 true 后移除本机行，失败时对未知结果提示先刷新，不自动重试。旧部署缺少消息集合路由（404/405）或删除路由（DELETE 404/405）时分别提示私信/删除功能暂不可用。详见[私信](messages.md)。 |
| 粉丝/关注列表 `GET /users/:userId/{followers,following}` | 本次接入只读 | 不需要登录，不附带会话凭据，不持久化列表；服务端最多 100 条、无 offset/cursor/总数，达到上限提示可能还有更多。点击用户可在当前 tab 打开作者主页；站点相对头像仍待 #63。单点 `.` / `..` ID 因 URI 规范化无法安全寻址，会报错而不是访问其他路由。 |
| 作者目录 `GET /authors?query=&locale=&limit=&offset=` | 已接入（关键词搜索 + 空输入浏览） | 依 no-wave ADR 0024，取代旧的 `GET /users?query=…`。无需登录，不附带会话凭据，关键词与结果都不持久化。目录只列**在该内容语言下有已发表作品**的作者——它是「可以去读的人」的名单，不是会员名单；有关键词时按相关度（整名、前缀优先，再按粉丝数），**没有关键词时按粉丝数排列**，所以输入框清空就是浏览，而不是一块空屏。每页 `limit=100`，用 `offset` 翻页：目录没有 cursor，所以下一页的名字就是「已经读过多少行」；第一页不发 `offset`，旧部署忽略该参数也照样是第一页。满页才显示「加载更多作者」，短页即结束；`offset` 到服务端上限 **100000** 就停，不再发出必被拒的请求（`400 BAD_USER_INPUT`）。关注人数会变，翻页期间排序可能移位，客户端按 `userId` 去重，`offset` 只按服务端收到的行数前进，去重不会让分页跳过。关键词上限服务端 200 字符，客户端收紧到 100（没有更长的笔名，更长的输入多半是粘贴事故），超长或首尾带空格的关键词在本地拒绝、不发请求。响应**不含头像、角色和关注状态**（这些依赖读者），所以行内头像退化为姓名首字，且不展示推测的关注关系；每行显示该语言的作品数与粉丝数，让排序依据可解释。目录结果只在内存保存一份，切换关键词立即失效，清空输入回到已经取到的那一页而不是重新请求。 |
| 分类读 `GET /categories`、`/categories/:slug`、`/categories/:slug/articles` | 已接入只读 | 搜索页「浏览分类」进入目录，点一个分类看它的文章。请求走匿名客户端（不带读者 token、不会触发续期），`locale` 随内容语言；目录只取 `limit=100` 一页，返回满页时明说「可能还有更多」，服务器没有总数；分类文章按 offset 分页（每页 20，短页即结束）。`GET /categories/:slug` 的 404 读作「这个分类不在了」，不是错误；目录本身 404/405 视为旧部署 → 「暂不提供」。名称由服务器按语言翻译、客户端不落盘，离线时没有分类页；分类成员关系也只在服务端。 |

## 改密服务端兼容性风险

使用 no-wave `7590ca98` 和 `58dc3419`、Node 22、本地内存 SQLite 及测试账号，实际调用注册、第二会话登录和改密，两版均复现：`PUT /me/password` 返回 200、撤销数为 2，但之后两个会话的 `GET /me` 均为 401，发起会话的 refresh 也为 401；旧密码登录 401、新密码登录 200。与文档声称的“保留发起会话”不符，复现和可能原因见 [no-wave #129](https://github.com/BrainEno/no-wave/issues/129)。另在同一隔离环境中，注入会话撤销失败后改密返回 500，但旧密码已不能登录、新密码可登录，另一会话的访问和 refresh 均仍为 200；证实密码更新与会话撤销可能部分成功，详见 [no-wave #132](https://github.com/BrainEno/no-wave/issues/132)。PostgreSQL 有相同的静态 ID 比较，但未实测；生产部署状态未知。客户端不能修复服务端事务或撤销策略，只能提前提醒重新登录，并在结果不明时避免制造确定性承诺。

注册、登录和改密均按原样传递密码（包括首尾空格），不保存到应用缓存或诊断；新密码按服务端规则校验 12–128 个 Unicode 码点、最多 512 个 UTF-8 字节。网络上的密码和会话必须通过可信 HTTPS 保护；开发明文 HTTP 仅限隔离测试账号。

## 验证边界与建议顺序

本次首页及正文适配的请求路径、分页、账号切换、离线和结构化阅读有客户端自动测试；`58dc3419` 的正文搜索与游标合约在隔离 SQLite 测试各通过一项，游标路由 mock 测试通过，PostgreSQL 未实测。真实后端、数据、图片和设备需独立验收。`latest` 仍保留现有离线缓存策略，精选、收藏榜与关注不写入也不读取这个列表缓存；通过单篇详情接口获取的文章会缓存，从卡片直接打开不会额外预缓存。旧 no-wave 缓存只保留压平后的文本，迁移不会凭空恢复原始结构。offset 翻页时服务端列表变化可能造成位移，客户端去重不能防止所有遗漏，下拉刷新可重新读取。

此轮正文适配的 SQLite v5 仅为文章缓存增添可空 JSON 列，不删除文章、草稿、偏好或阅读历史。旧 no-wave 缓存根据服务端文章 ID 标记为可能不完整，早期本地 Markdown 保留原行为；新版应用重新联网获取后写入新数据。

后续本地草稿隔离使用 SQLite v6：新草稿按后端、账号和文章隔离；未记录归属的旧 SQLite 草稿保留但不自动显示或分配（Isar 时代的草稿在 #107 后不再导入）。参见[旧草稿说明](unclaimed-drafts.md)。旧版应用回退打开新版数据库并未验证，降级可能再次向错误账号展示旧草稿，升级/降级前应自行备份设备数据。

接下来优先补齐：① 修复并部署服务端改密会话问题（[#129](https://github.com/BrainEno/no-wave/issues/129)、[#132](https://github.com/BrainEno/no-wave/issues/132)）；② 富文本完整、安全往返与并发更新策略（含结构化草稿的发布）；③ 邮件找回/重置密码（需服务端配置邮件投递）；④ 私信的后续能力（参与者增删、未读角标与推送仍需服务端投递能力）。语言版本的跨语言回收站与“这篇作品的其它语言”入口需要服务端补接口，客户端无法单方面提供。分类管理与角色、社交列表可作为独立功能；具体界面和邮件/推送部署能力应分别验证，不将管理接口或未实现的服务器能力伪装成客户端功能。
