# no-wave API 与 Flutter 客户端差距（2026-11-01）

本表静态核对 no-wave 默认分支快照 [`ea276a5e`](https://github.com/BrainEno/no-wave/tree/ea276a5e4b6a1b2e11c2fa4636fddcda4ac489fb) 的 [`routes.ts`](https://github.com/BrainEno/no-wave/blob/ea276a5e4b6a1b2e11c2fa4636fddcda4ac489fb/apps/api/src/transport/rest/routes.ts)、handler、数据校验和客户端实际调用。相对前次快照 `d8f8d979`，新增公开精选及编辑排序接口，并把 `sort=popular` 改成全时段累计。更早的 `55a24bd` 到 `d8f8d979` 则增加账号修改、关注流、排序及编辑角色等。源码存在不代表某个部署已经升级、邮件可投递或移动端联调通过。

## 接口与用户能力

| 能力 / API | 客户端状态 | 语义与后续 |
|---|---|---|
| 公开最新文章 `/articles`，点赞、评论、标签、作者、关注，发布、软删和恢复 | 已接入 | 延续现有实现；删除恢复后作品为服务端草稿。 |
| 关注流 `GET /me/feed` | 本次接入 | 仅登录用户；只含被关注作者的已发布文章，取消关注后刷新消失。无关注或无作品时返回空，不回退到公共流。每页 10 条，使用 offset；网络不可用时明确报错，不把无账号作用域的公共缓存当关注流。 |
| 精选 `GET /featured` | 本次接入只读 | 登录与否均可查看，按编辑指定顺序分页，最多 20 篇；空列表不回退公共流，不使用公共缓存。编辑端 `PUT /featured` 尚未接入。旧部署没有此接口时会显示请求错误。 |
| 最多收藏 `GET /articles?sort=popular` | 已接入 | 此快照对**全部已发布作品**按累计收藏数排序；旧部署可能仍使用近 30 天窗口，API 不提供版本协商。客户端避免写死时间范围，网络不可用时不伪造排序。 |
| 账号：`PUT /me/password`、`PUT /me/email`、`GET /me` 返回邮箱/验证状态 | 未接入 | 改密需当前密码，保留当前会话、撤销其他会话；改邮箱也需当前密码，更换地址后变为未验证。客户端目前仍显示登录时的本地邮箱。**错误当前密码也可能是 401**，接入时需避免将其当作 access token 过期而盲目重复提交。 |
| 找回/重置密码、邮箱验证与重发 `auth/*`、`POST /me/email-verification` | 未接入 | 需安全的链接处理、匿名防枚举和邮件状态提示；后端邮件默认关闭，实际投递未验证。 |
| `contentBlocksVersion: 1` 富文本、结构化 v0、正文多图 | 部分读取，未完整适配 | 现有解码会压平格式，额外图片可能仅显示说明；本次在更新前检查新鲜的服务端正文和摘要，阻止已知不可往返的块被普通编辑器覆盖，并回传已有摘要。**这不是富文本读写支持**，复杂正文请使用 no-wave 网页。服务端未提供条件更新，此检查不能防止检查后另一个设备并发修改；客户端会重新生成正文块 ID，服务端仍可能重算空摘要。 |
| `GET /me/articles`（含服务端草稿） | 未接入 | 当前“我的文章”读公开作者列表，不能完整查看服务端草稿；恢复到草稿的作品不能依靠该列表重新发布。本机自动草稿与服务端草稿不是同一数据。 |
| 通知 `GET /me/notifications`、`unread-count`、单条/全部已读 | 未接入 | 需按账号隔离、明确刷新/失败与已读语义；后端尚无移动设备令牌和推送投递，不能宣称实时推送。 |
| 私信 `conversations*` | 未接入 | 需要受信参与者鉴权、消息游标分页、已读语义、账号隔离；创建会话和发送消息需要稳定的 `Idempotency-Key`，失败/重试不能制造重复消息。 |
| 用户搜索、粉丝/关注列表 `GET /users*` | 未接入 | 可在独立社交功能中接入；关注/取关本身已存在。 |
| 分类 `categories*`、编辑角色 `PUT /users/:id/role`、分类维护 | 未接入 | 最新后端规定分类由编辑共同维护；标签仍对登录作者开放。角色和权限由服务器强制，不能只靠隐藏按钮。 |
| 媒体 `/api/media/:id` 别名 | 不需要改现有上传路径 | 客户端已由资源 id 构造版本化 `/api/v1/media/:id`；新别名主要使网站相对地址可直连 API。媒体上传仍无幂等键/删除接口，不安全地自动重试可能产生孤儿资产。站点相对头像 origin 问题另见 [#63](https://github.com/BrainEno/flutter-blog/issues/63)。 |
| 新建文章 `Idempotency-Key` | 未接入 | 服务端现支持相同 key + 相同请求重放；客户端普通发布尚未固化跨重试 key。离线 outbox 的独立草稿 PR 仍待评审，不能声称已可靠离线发布。 |

## 验证边界与建议顺序

本次首页适配的请求路径、分页、账号切换及离线行为有客户端自动测试；真实后端、数据、邮件与设备需独立验收。`latest` 仍保留现有离线缓存策略，精选、收藏榜与关注不写入也不读取这个列表缓存；查看单篇文章仍沿用既有文章缓存。offset 翻页时服务端列表变化可能造成位移，客户端去重不能防止所有遗漏，下拉刷新可重新读取。

接下来优先补齐：① 富文本完整、安全往返与并发更新策略；② 账号密码/邮箱与邮件验证；③ 服务端草稿；④ 通知和私信。分类管理与角色、社交列表可作为独立功能；具体界面和邮件/推送部署能力应分别验证，不将管理接口或未实现的服务器能力伪装成客户端功能。
