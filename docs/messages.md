# 私信（会话）

私信只有服务端一个来源：no-wave 的 `conversations*` REST 接口。**没有推送，也没有
轮询**：客户端能做的是「进页面读一次」，加上下拉刷新、明确的「全部已读」动作、仅创建者可用的删除会话和成员管理。

## 与服务器的契约

| 接口 | 客户端用法 |
| --- | --- |
| `GET /conversations?limit=` | 收件箱唯一的数据来源；请求 50（服务端 `1..100`，默认 50） |
| `GET /conversations/{id}` | 打开会话页时读表头：参与者、未读数、最后一条 |
| `GET /conversations/{id}/messages?limit=&before=` | 消息页（最新一页 100 条，oldest first）；`before` 是屏上最旧一条的 id |
| `PUT /conversations/{id}/read` | 显式「标为已读」；无游标，服务端一次性把它已收到的全部标为已读 |
| `DELETE /conversations/{id}` | 仅创建者可用；永久删除整个会话（含所有消息、参与者、相关通知及 outbox 事件），`{data:true}` 表示本次删除，`{data:false}` 表示此前已不存在 |
| `PATCH /conversations/{id}/participants` | 仅创建者可用；body 可含 `addUserIds` / `removeUserIds`，每个数组最多 20 个不同的 userId；返回更新后的会话 |
| `POST /conversations` | 新建会话，body `{participantIds:[recipientId]}`，**必须**带 `Idempotency-Key` |
| `POST /conversations/{id}/messages` | 发送，body `{body}`，**必须**带 `Idempotency-Key` |

一行会话形如 `{id, createdBy, participantIds[], createdAt, lastActivityAt,
unreadCount, lastMessage?}`，一行消息形如
`{id, conversationId, senderId, body, createdAt, duplicate}`。接口**只给 userId**，
没有昵称和头像——见下面的「参与者名字」。

不对称的两处状态码是有意的：

- **会话不存在**和**你不是成员**在会话端点上都返回 404。客户端不区分，也不猜，
  页面统一说「会话不存在，或你不属于这个会话」，并且**不提供重试**——重试不会让
  它存在。
- **非成员读消息**返回 403（与会话 404 不对称）。客户端原样呈现为同一句「没有
  权限查看」的缺失态，不伪造 404 语义。

## 客户端行为

- **进页面读一次 + 下拉刷新。** 不轮询、不定时器、不假装推送。
- **不落盘。** 私信只活在页面内存里；离线打开就是离线失败，不拿旧列表冒充新状态。
- **账号围栏全程携带。** 每次请求带发起时的 `NowaveSessionFence`；请求在途时切换
  账号，结果被丢弃，界面按新账号重读。列表页订阅 `identityChanges`，账号一变就
  重新读一次。
- **旧部署说「暂不提供私信」。** 缺少这组路由的部署在集合端点上返回 404/405，
  界面明确提示服务器暂不提供私信，而不是显示空列表让人以为「没有私信」。
- **已读是显式动作。** 会话页顶部只在有未读时出现一条横幅，说明服务端会把**截至
  此刻收到的全部消息**标为已读（包括本机还没加载出来的部分），用户点了才写。
  只有服务端明确回 `{data: true}` 才把未读数清零并显示「已标为已读」。
- **删除仅对创建者开放，且是全局永久删除。** 这不是只隐藏自己的收件箱：服务端会
  删除会话、所有消息、参与者记录及相关通知/outbox 事件，其他参与者也无法再访问。
  入口只向创建者显示；提交前弹出说明全体影响且不可撤销的破坏性确认，只有服务端回
  `true` 后才从本机列表移除。回 `false` 表示会话此前已不存在，客户端刷新收件箱；
  网络/超时/无效响应等无法确认结果时不自动重试，并提示先刷新再决定是否重试。
  旧部署对 DELETE 回 404/405 时显示服务器暂不支持，而不误报为「会话不存在」。
- **参与者管理仅对创建者开放。** 成员选择只使用作者搜索结果（当前内容语言下有已发表作品的作者）；API 本身只校验 userId 字符串，不验证账号是否存在。每次添加都先确认：新增或重新加入的人可读取**全部历史消息**，加入前的消息不会计为未读。移除会撤销对方当前访问权，但不会删除消息；若之后重新加入，对方仍能查看完整历史。服务端也禁止创建者移除自己。成员更新失败且结果无法确认时，不自动重试，提示重新打开会话核对；旧部署的 PATCH 路由缺失时提示暂不支持。
- **发送不产生重复消息。** 见下节。

## 幂等键

创建会话和发送消息在服务端都是**强制**要求 `Idempotency-Key` 的写操作。

- 编辑器持有幂等键，**cubit 从不自己生成**：同一段文本的重试复用同一个键，服务端
  重放已存储的消息（回包里 `duplicate: true`），不会多出一条；改文本等于换了意图，
  换新键。
- 新建会话同理：同一个收件人重试复用同一键；401/网络失败后重试不会变成第二个会话。
- 若服务端回答 `409 IDEMPOTENCY_CONFLICT`（同键不同 body），说明**键**才是问题：
  客户端丢弃该键，下次尝试重新生成。这和普通的状态冲突（`server.CONFLICT`，
  提示「刷新后重试」）在文案上分开。
- 服务端在建会话上不做「同一对参与者只保留一个会话」的去重，所以「发私信」入口
  先查已有列表：已存在与这个人的一对一就**直接打开**，不新建。收件箱只显示最近
  50 个会话，找不到时才走新建，新建的结果会再读一次列表。

## 参与者名字

会话只带 userId。名字是通过公开作者资料（`GET /authors/{id}`）逐个人解析的：

- **一页最多解析 12 个**，并发 4；拿不到的保持「未知读者」，绝不把 UUID 当名字显示。
  下拉刷新解析下一批。
- **失败不是名字**：404（没有这个作者）记下来，列表不再反复问；离线/超时/5xx 不记，
  下次还会再试。
- 缓存上限 200，公开资料可以跨账号复用，不清空。

## 入口与路由

- `/profile/messages` 收件箱（个人中心菜单「私信」）。
- `/profile/messages/:id` 会话页。
- `/profile/messages?to=<userId>` 作者页「发私信」：带上收件人，收件箱决定是直接
  打开已有会话、还是给出「和某人开始私信」的卡片。作者页自己不建会话，否则会
  出现同一个人的第二条会话。
- 通知收件箱里 `message.created` 若带 `conversationId`，多一个「打开会话」按钮。

## 已知限制

- 收件箱没有游标：只有最近 50 个会话，占满一页时界面说明更早的会话不可见。
- 每次参与者更新最多添加和移除各 20 人；添加选择仅覆盖当前内容语言下可搜索到的已发表作者，非公开/无作品账号不能从此处加入。
- 没有推送，也没有未读角标：未读数只在收件箱与会话页里按读取时的状态显示。
- 服务端会话 id 在 Web 代理侧按 UUID 校验；Flutter 直连 API，不依赖该约束。
