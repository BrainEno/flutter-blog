# 功能清单（详细版）

> 状态：active ｜ 最后核对：2026-11-19 @ 2a86bb2

> 根 README 只保留一行一项的摘要（#298）；这里是每项功能的完整边界说明。
> 各功能的专题文档见 [文档索引](README.md)。

- 账号：邮箱注册（注册即登录，无邮箱确认步骤）/ 登录 / 退出，
  个人资料编辑（昵称、网站、头像）
- 文章：传统编辑器（标题 + 正文，和 no-wave 网页端一样）发布 / 编辑 / 删除。正文是
  与 no-wave block 一一对应的 **Markdown**：无格式的正文仍写成 v0，用了标题、引用、
  列表、代码、图片、链接或行内样式就写成 v1，网页端显示同样的结构；结构化文章只要能
  无损往返就直接在编辑器里打开，否则提示到网页端编辑，避免覆盖格式。键盘上方的格式
  工具栏（撤销/重做、H2–H4、粗斜删下划、代码、引用、列表、链接、插入并上传图片）、实时
  高亮、回车续写列表、字数与阅读时长、专注模式和编辑/预览切换
  （[编辑器路线图](editor-architecture-roadmap.md)）。入口：首页「+」、个人中心「撰写新
  文章」、我的文章右下角写作按钮；点按文章编辑。每篇文章的「⋯」（或长按）是文章操作：
  编辑、发布草稿 / 转为草稿（取消公开，需确认）、删除进回收站。发布状态的切换不打开编辑器：
  把这一行的标题、正文、标签和语言版本原样带 `publish` 重新写入，以这一行读到的版本做条件
  写入（别处改过就提示并刷新，绝不覆盖），封面、分类和摘要保持服务端原样；编辑器无法无损
  表示的正文只能在网页端切换，缺少版本信息的行提示先刷新。封面图与标签均可选
  （仅标题与正文必填），封面上传后由服务端统一转码 WebP、资产不可变。封面：编辑器里的
  封面框是阅读页头的 16:10（最宽 400，平板上不把正文挤出首屏），所见即读者所见；从相册选图后先进裁剪页——照片在固定的
  16:10 框下拖动、双指缩放（最多 4 倍），框外两侧加暗、中间描边的就是网格卡片（4:3）
  保留的部分；确认后在后台 isolate 用纯 Dart 的 `image` 包裁成 JPEG（最宽 1920 像素，
  相机照片的 EXIF 方向先摆正），再作为封面上传。封面框下的一排操作：选择 / 更换图片、
  从媒体库选择、调整裁剪（回到未裁剪的原图、停在上次的位置；只对本次从相册选的或队列里
  恢复的封面出现）、移除封面 / 恢复原封面（撤销本次的选择：新文章回到无封面，已有文章
  不带封面写入、服务端保留原封面——no-wave 的写入契约里空封面就是「保留」，所以 App
  不提供删除已发布封面）。取消裁剪保留之前的封面；解码不了的格式按原图使用并提示
- 浏览：分页 Feed、下拉刷新、滚动加载更多、按标签筛选、文章搜索
  （含防抖与结果上限；已升级的服务端也搜索正文块文本，旧部署可能只查标题或摘要）；搜索页
  另有本机**离线书库**，可在不联网时浏览当前服务器/内容语言的有界公开缓存，并以子串匹配
  标题、作者、标签和可读正文，提供命名空间级清空（不是完整服务器搜索或下载列表，见
  [离线书库](offline-library.md)）。文末相关阅读推荐（服务端 related，最多 6 篇）；首页可切换
  最新、编辑精选、按收藏排序的作品，以及登录后查看关注作者的作品。精选、收藏榜和关注
  仅在线读取，不能用公共缓存伪造排序或关注关系。
- 最近搜索：登录后，搜索框为空时列出最近 8 次搜索（`RecentSearches`，
  `lib/features/blog/presentation/search/recent_searches.dart`），点一下即重新搜索并移到最前，
  每行末尾的 × 单独移除，「清空」可在提示条里撤销。只记录按下键盘「搜索」或点开结果时的
  搜索词，边输入边出现的中间词不记；大小写不同视为同一次。按后端与账号保存在本机 SQLite
  `metadata` 表（不需要迁移），换账号立即切换，未登录不显示也不记录，从不上传。
- 列表摘要：首页、搜索、标签、分类、作者页的文章行（以及收藏/我的文章网格）在标题与作者
  之间显示一段摘要（`articleExcerpt`，`lib/features/blog/domain/reader/article_excerpt.dart`）。
  作者自己写的摘要（Notion 的 `Excerpt` 属性、网页上填的摘要）原样显示；服务端在摘要留空时
  会从开头自动截一段，这种「只是正文开头」的摘要（与网页 `repeatsArticleOpening` 同一判断）
  被换成客户端自己的截取：正文前 150 字（`AppLimits.articleExcerptCharacters`，跳过图片与
  代码），截断处末尾的标点、符号一律去掉，最后一个字后面接 `...`；英文不在单词中间截断。
  正文本身不足 150 字时原样显示、不加省略号。摘要随文章缓存（数据库 v20），离线列表一致。
  显示时另有行数上限：普通行最多 3 行（`AppLimits.excerptRowLines`），头条最多 4 行
  （`excerptLeadLines`），超出以省略号结尾。作者写的摘要最长可到 2000 字，150 字的中文截取
  在手机一栏里也有七行左右，行数上限保证一行文章不会被摘要撑得太长。
  文末相关阅读（`quiet` 行）不显示摘要。
- 互动：点赞 / 取消点赞（乐观更新 + 服务端状态校准，显式置态），个人收藏列表，
  评论（纯文本 v0：嵌套回复、最旧在前；按需加载后续页，每页最多 50 个顶级评论，
  回复树随根返回，计数仅表示已加载的评论（含回复）；发送带幂等键安全重试，自有评论删除需确认且级联子回复；
  未登录显示登录提示）
- 评论草稿：登录后在评论框里打了字没发出去，离开文章、切到后台或关掉 App 都不会丢，下次打开
  同一篇文章时原样回到框里（`CommentDraftKeeper`，
  `lib/features/blog/presentation/comments/comment_draft_keeper.dart`），连同「回复 @某人」的
  对象；框下方提示「已恢复你上次没发出的评论」，可一键「丢弃」并在提示条里撤销。停止输入 1 秒
  （`AppDurations.commentDraftSave`）后保存，离开时立即保存；发送成功即删除，发送失败保留。
  已经开始输入或已选回复对象时，旧草稿不会覆盖。按后端与账号保存在本机 SQLite `metadata` 表
  （不需要迁移），每个账号最多保留最近 20 篇文章的草稿（`AppLimits.commentDrafts`）；换账号时
  先把上一位的输入存给上一位，再换成新账号自己的草稿，未登录不保存，从不上传。
- 作者：公开作者主页（资料、粉丝/关注数、TA 的文章），从搜索页按昵称或用户 ID
  发现作者，也可从作者页查看粉丝和关注用户，或从个人中心进入自己的作者页。
  搜索页的空输入框就是**作者目录**：只列当前内容语言下有已发表作品的作者，
  不输入关键词时按粉丝数排列，输入后按相关度搜索——名单本身说明「这里有人可读」，
  而不是把所有注册账户摆出来。作者目录与关系列表仅在线、无需登录且不附带会话凭据；
  每页 100 人，底部「加载更多作者」按 offset 续读（服务端上限 100000，短页即结束；
  翻页期间粉丝数变化导致的重复按 `userId` 去重，不重复显示）。搜索词和结果
  资料仅保留在页面内存，目录不带头像（头像依赖读者，改成姓名首字）；内容语言随
  界面语言推导。
  关注 / 取消关注由服务端校准（重复请求幂等，防连点；未登录引导登录；自己
  主页不显示关注按钮）。站点相对头像只在配置可信 `WEB_BASE_URL` 时解析；未配置或地址不安全时
  显示中性占位，不从 API origin 猜测。
- 阅读统计：阅读历史页顶部的摘要卡片，显示近 7 天篇数、当前连续阅读天数、
  累计篇数、最长连续天数和 7 天活动条。完全由已加载的本地历史推算，不新增存储、
  不联网；历史每篇只保留最近一次阅读，所以按“每篇文章最近一次阅读的日期”计数，
  重读旧文章会把它移到今天。当前连续天数在今天尚未阅读时从昨天起算；设备时钟
  超前写入的未来时间不计入窗口与连续天数。读屏把活动条读成一句完整描述。
- 阅读：设备本地阅读历史（按账号隔离，退出时尽力清理；从卡片打开的文章也会记入），
  记住每篇读到的位置（按正文计，不含评论区）：再次打开时底部出现「从上次停下的地方继续」，
  点一下滑回去，自己往下读过那里就收起；历史行在日期后写「读到 42%」或「已读完」。
  **列表里的阅读标记**：首页、搜索、标签、分类、作者页的文章行和文末相关阅读，在作者名之后、
  箭头之前写同样的「读到 42%」/「已读完」；收藏、我的文章网格写在日期后面（不改变卡片高度）。
  与历史页同一套用语和阈值（不到 5% 不标，95% 起算读完）。只对登录用户、按账号隔离，
  取自本机最近 200 条阅读历史（`lib/features/blog/presentation/viewer/reading_marks.dart`
  包住历史存储，阅读页保存位置的同时列表就更新，不额外查询）；切换账号立即清空再读新账号的，
  退出登录随历史一起消失。阅读字号：
  应用栏的「字号」按钮打开五档（小 / 标准 / 大 / 较大 / 特大，正文 16–24）选择，选的同时
  后面的正文就重新排版，并停在原来读到的那一段；只放大正文（小标题、代码、图注同比例），
  叠加在系统字号之上，对所有文章生效，保存在本机（`metadata` 的 `reader_text_size_v1`）。
  **文章目录**：正文里有 3 个及以上小标题（`AppLimits.outlineMinHeadings`）时，应用栏多一个
  「目录」按钮，打开后列出各级小标题（按文章实际用到的最高一级起算缩进，最多缩进两级；引用或
  列表里的标题不算），当前读到的那一节用橙色竖线标出（读屏读作「已选中」），列表比面板长时
  自动滚到那一节。点一行就滑到那个小标题（系统要求减少动态效果时直接跳过去），位置照常记入
  阅读进度，并收起「从上次停下的地方继续」；朗读进行中则松开跟随，和手动滑动一样。v0 Markdown
  与结构化正文都适用（`lib/features/blog/presentation/viewer/article_outline.dart`、
  `article_outline_sheet.dart`），不联网、不存储。分享文章到系统
  分享面板（标题 + 摘要 + 指向 no-wave web 文章页的 canonical URL，需配置
  `WEB_BASE_URL`），`nowave://article/<slug>` 深链在应用内打开同一篇文章
  （见 [分享与深链](deep-links.md)）
- 草稿预览：阅读页打开未发布的草稿时，标题下注明「草稿预览，只有你看得到」，作者本人可
  从提示里的「编辑」直接进编辑器（在「我的」分支用该分支的编辑器，其它分支用首页的），保存
  或发布后返回即重新读取预览。草稿不显示分享、收藏，文末也没有相关阅读和评论；预览不计入
  浏览量、阅读历史和阅读进度，也不查询收藏状态。只有网页端编辑器能无损保存的正文不提供
  「编辑」按钮（`viewer_article_body.dart`、`blog_viewer_page.dart`）
- 数据导出：个人资料及最多 100 篇简体中文已发布作品的部分文字导出为 JSON，
  经系统分享面板保存；不含服务端草稿、其他语言及完整正文格式或图片，**不是完整备份**
- Notion 导入 / 导出：编辑器「从 Notion 导入」可选择本机文件——Notion「导出 → Markdown & CSV」
  得到的 ZIP（含分卷 ZIP）、单独的 `.md` 页面或 no-wave JSON bundle——也可粘贴页面的 Markdown
  或 bundle。Markdown 在本机按 no-wave web 端同样的规则转换（文件名中的 Notion 页面 ID 决定
  身份，同一文件从 web 和 app 导入得到同一篇文章；无 ID 的文件按文件名、粘贴的页面按标题识别；
  缺少「# 标题」行时用文件名作标题并提示），转换中无法完整保留的内容（未识别的属性、表格、
  嵌套列表、找不到或不支持的本地图片等）在预览前按类别列出。数据库 CSV（优先 `_all.csv`）按
  web 端规则补全页面中为空的日期、摘要、封面、发布、别名与标签（按「# 标题」再按文件名匹配行，
  重名不补；整列都是勾选值才当作「发布」），每页说明补了什么。默认全选所有页面；以 `English`
  关联的作品与其英文版一起勾选或取消（服务端拒绝只导入其中一页），并在列表中注明。
  导入完成后，结果读取一次你自己的文章列表：已发布的文章可直接「打开文章」（阅读页叠在编辑器
  之上，返回即回到编辑器）；存为草稿的注明可在「我的文章」中编辑和发布；列表读取失败或未列出
  的作品不作说明。
  导出中的本地 PNG / JPEG / WebP 图片（ZIP 内或与页面一同选择）**在预览前**逐张上传到你的媒体库
  并替换为媒体地址（每次预览最多 60 张，单张不超过 8 MiB；按内容判断类型）：服务端拒收的图片
  跳过并列出名称，其他失败则停止且不预览；已上传的图片在本次导入中不会重复上传，不自动重试。
  预览后未导入的图片会留在媒体库中不被引用。
  ZIP 只在内存中读取：拒绝不完整 / 加密 / ZIP64 / 分卷压缩包，最多 2000 个条目、200 个页面，
  所选文件合计不超过 64 MiB，其中解压的 Markdown 与 CSV 合计不超过 8 MiB（边解压边计数），
  图片只在上传时解压。服务端报告中的问题代码显示为说明文字；
  每账户每 10 分钟最多 10 次（预览也计入），被限流时说明需等待多久。也可把已保存
  的编辑内容导出为 bundle；两者均由用户显式发起，不等同于连接或浏览 Notion 数据库
  导入需支持预览计划保护的 no-wave 服务端（#308）；旧服务端缺少计划时不会允许确认。
  计划只在内存中使用，选择或账号变化、过期或失败后需重新预览。服务端按作品保护，
  多作品可能部分成功；超时或断线后先检查文章再预览，不会自动重发。
- 草稿：按 API 后端、账号和文章隔离的本地草稿、恢复 / 丢弃对话框及 2 秒
  防抖自动保存；发布前保存快照，成功后仅在快照未变化时尝试清理。旧版无法
  证明归属的草稿保留但不自动显示或分配，服务端草稿是独立功能（菜单「保存到本机」）
- 服务端草稿与摘要：编辑器菜单「存为草稿（仅自己可见）」把文章以未发布状态写到
  no-wave（新文章或更新都可以，离线时同样进发布队列并标明「将存为草稿」）；已公开的
  文章对应「转为草稿（取消公开）」，需确认。打开草稿时编辑器顶部注明只有自己可见，
  「发布」后读者才能读到。正文下方可写可选摘要（≤2000 字），留空由服务端根据正文
  生成；不改动时保留文章原有摘要，清空则请服务端重新生成
- 发布队列（#23）：发布时网络失败或离线，会把这篇文章连同封面存进本地队列，联网
  后自动重试；每次尝试都带同一个幂等键，因此「响应丢了」不会变成两篇文章。队列按
  账号和 API 后端隔离，只由当前账号发送；账号过期时暂停而不消耗重试次数，被服务端
  拒绝的内容才停下来等人处理。个人中心 → 发布队列可查看、立即发送、重试或移除，
  详见 [发布队列](publish-queue.md)
- 离线：最新列表及通过详情接口取得的文章会缓存在 SQLite，可离线阅读；精选、
  收藏榜、关注等网络列表不写入普通列表缓存。结构化正文随已缓存文章保存，图片
  不保证离线可用。离线书库只读当前 API 后端和内容语言的公开缓存，列表与搜索不发
  网络请求；其估算大小不包含图片/WAL，清空不会碰草稿、队列、历史或其它命名空间。
  旧版 no-wave 缓存可能已经压平结构，升级后会提示可能不完整，联网重新获取可恢复。
  首页按每页 10 条读取缓存并标明可能不完整或过期；其他网络操作离线时快速失败并提示
- 语言与无障碍：简体中文 / 英文界面跟随系统语言；日期和数字按区域格式化，
  图片与操作提供语义标签，常用操作支持键盘与较大的字体；主题支持亮 / 暗 /
  跟随系统并在本地持久化
