# Structured editing session recovery

The recovery store is local infrastructure, **not a publishing path**. It is
not currently connected to the editor or publish queue. It only addresses an
existing article by backend namespace, signed-in account, stable server article
ID and explicit content locale. It cannot recover a new article without a
server ID. Its base/body and base/session metadata snapshots are committed in
one SQLite row; local revisions and exact-value comparisons prevent stale local
editors from overwriting or deleting a later snapshot. They are not server
versions and cannot prevent a remote GET/PUT race.

## What is known

At no-wave revision `8a4fd1fb28fbc42d6e9105ee799dbda8d36e3d65`, REST article
writes require the update slug and `publish`, accept an explicit locale and
one versioned `contentBlocks` array, and accept title, summary, optional work
type, tag IDs and category IDs. An empty summary is regenerated by the server.
The article response may provide ID, locale, slug, title, summary, work type,
tags and categories, but callers must verify each value from the actual source
and requested edition. The existing Flutter `BlogModel` is not an exact source
for all those fields: its tag/category mapping can omit malformed entries, it
uses defaults for missing values, and `isDraft` defaults to false when status
is absent. A false `isDraft` therefore cannot establish published status.
The recovery model never infers a missing value or constructs it from a rendered
or flattened body. The current plain editor and plain publish queue are not
suitable for structured writes and remain unchanged.

Session fields can be null (unknown), while empty title/summary/slug and empty
selection lists remain explicit values. Tag values are editor-facing names;
category values are IDs. A known selection records whether it was touched, so
an untouched selection is different from an explicit clear. Publication state
is `draft`, `published`, or unknown; no unknown status is converted to publish.
The stored metadata is recovery input, not a validated wire request: incomplete
text, blank summary, unknown tag resolution, cover handling, changing server
contracts and live authorization all need review before any write.

## Cover and migration

A cover can be unknown, unchanged, explicitly removed, an exact safe URL, or
local JPEG/PNG/WebP bytes. Local bytes are copied into the SQLite snapshot
as base64 in the same atomic transaction, not stored as an ephemeral picker
path. The 8 MiB limit matches the audited API's binary image cap. MIME and
size are checked, and CRC32 detects common accidental byte damage; CRC32 is not
authentication, and image decoding and upload are not verified. Failure
or corrupt/missing bytes aborts recovery rather than silently dropping the
cover. Replacing a session requires an exact local snapshot; a failed write
leaves the previous snapshot intact. Temporary selection state before a caller
successfully saves is not durable.

Schema v15 adds nullable metadata columns to v14 rows. Null means the old
body-only draft never retained metadata; the upgrade does not guess a title,
cover, summary, status or category. Earlier plain and ownerless drafts are not
migrated into structured sessions. A new client can inspect and augment a v14
row while its original base metadata remains unknown. Rolling a v15 database
back to an older app has not been validated and requires a backup/migration
plan. Storage is not newly encrypted, and base64 covers increase database size
and copy/memory cost; no real-device performance or durability run is claimed.

## Authoring read boundary

At no-wave revision `8a4fd1fb28fbc42d6e9105ee799dbda8d36e3d65`, REST
`GET /articles/:slug` reads published work only; it cannot retrieve an author's
server draft. `GET /me/articles?locale=...&limit=100` is authenticated, includes
published and draft editions, filters the requested locale and returns at most
100 records without an offset. The underlying persistence has `getMyArticle`,
but there is no corresponding owner-detail REST route. An article absent from
the window must therefore be reported as unavailable in the window, not as
deleted, non-existent, or published. Older deployments and network failures
also cannot establish absence. The client never substitutes a public detail
read or another locale for this private read.

The authoring reader validates account, article ID and returned locale, keeps
full raw response fields and reports metadata gaps or future top-level fields
explicitly. Unknown or malformed block structures are not flattened. `status`
is unknown when absent or unrecognized, rather than inferred from a boolean;
nullable metadata and untouched taxonomy selections remain distinct. The
returned response is **not** a valid write request. Local recovery and the
remote edition are returned separately, and reads never overwrite local edits.
The caller must fence its own route/edit generation when applying results, and
use the local revision token when subsequently saving or discarding. Local read
failure blocks automatic initialization from a remote response. A successful
read is not a server-side compare-and-swap or concurrency guarantee.

## Local-only session coordinator

`LocalStructuredSession` is an isolated domain component, not an editor screen
or a remote-write path. The existing author list's domain `Blog.id` is a slug,
not the stable article ID (the latter currently lives in the data model), and
its content is a lossy reading projection. A future UI needs a domain-level
exact edition identity before it can safely open this coordinator; it must not
import the data model or use a slug as a recovery key. Existing Markdown editor,
router, write guards and publish queue are unchanged.

The coordinator opens the exact owner/edition and requires an explicit choice
when a local recovery exists. Cancel does not delete it; confirmed discard uses
its exact local CAS token. A stale or failed discard never replaces another
editor's row. Offline, unsupported and incomplete remote responses can still
leave an existing local session recoverable; they never become a blank article.
Base comparisons are advisory, including when represented fields match. Unknown
metadata, an unknown cover, future fields and unobserved changes cannot prove
that the server did not change.

Each accepted edit is an immutable validated structured snapshot. Saves are
serialized, coalescing later edits behind an in-flight write, and retain the
original base; first creation and subsequent updates use the store's atomic
create-or-CAS operations. A storage error retains the latest pending edit in
memory for an explicit retry; a CAS conflict stops writes rather than rebasing
or overwriting another editor. Consumers must surface these states and keep the
session open, not claim a successful save. `flush` reports durability only when
the local operation completed; `close` waits for admitted writes and refuses
unsaved failure unless the caller explicitly acknowledges abandonment. That
acknowledgement never deletes the previously persisted row.

An identity or generation change invalidates the public state immediately.
Writes admitted before the change may complete only in the captured original
backend/account/article/locale namespace, including edits queued behind an
in-flight save; new edits are rejected. A failed write during sign-out remains
pending and `close` refuses silent abandonment. Already delivered snapshots
cannot be revoked: UI consumers must clear their own references on identity
changes. A process kill, database failure or explicitly abandoned in-memory
edit can still lose changes that did not reach SQLite. Existing recovery data
is not encrypted by this component.

Upstream no-wave main was re-audited at
`e54e10930f2999fad8fe65aadcdeea435278ded7`: the authoring REST list still
limits each locale to 100 without an offset, and article writes still have no
atomic compare-and-swap precondition. No schema migration or server write is
introduced here. Widget accessibility, real devices, production server and
signing remain unverified until a user-facing editor exists and is tested.
