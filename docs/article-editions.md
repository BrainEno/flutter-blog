# 语言版本（article editions）

no-wave 里一篇文章的 id 是**作品**，`(id, locale)` 才是其中**一版译文**。同一个 slug
可以同时存在 `zh-CN`、`zh-TW` 和 `en` 三种译文。本页说明客户端怎么读、怎么写，以及
客户端无法单方面保证的部分。

## 服务端契约（核对自 no-wave `4f6c7d82` 与 `docs/api/authoring-locales.md`）

| 接口 | 语义 |
|---|---|
| `POST /articles` body `locale` | 省略视为 `zh-CN`；只接受 `zh-CN`、`zh-TW`、`en`，其他值 400。 |
| `PUT /articles/:articleId` body `locale` | 插入或**替换**这一版译文，不会改名或删除另一版。slug、作品类型、发布状态、删除都是整篇作品的属性。 |
| `GET /articles/:slug?locale=` | tag 非法返回 400；某语言没有译文时不会串到另一种语言。 |
| `GET /me/articles?allLocales=true` | 账号作用域，按语言各读一次，每条独立返回，`updatedAt` 倒序合并；`limit`（1–100，默认 50）**按语言**计，因此一次最多 300 条。与 `locale` 互斥，冲突或非法选择直接 400，不猜。 |
| 同上，响应的 `meta.locales` | 服务器读过哪些语言。旧部署会忽略 `allLocales`，照常 200 但只给 `zh-CN` 且**没有**这个标记。 |
| `POST /articles/:articleId/restore?locale=` | 恢复需要 `locale`；给错语言会被当成“没有这版译文”。 |

删除、下架一版会影响整篇作品；恢复任意一条墓碑会把整篇作品恢复成草稿，并保留所有译文。

## 客户端行为

- **读**：`Blog.locale` 记录文章体来自哪一版；标题、正文、标签都是该版的内容。离线缓存
  行本来就带 `content_locale`，所以缓存命中也知道版本。
- **写**：编辑器打开的是哪一版，`PUT` 就写哪一版；离线队列把这条 `locale` 落进 SQLite
  （schema v11），几天后的重放不会因为界面语言变了而改写另一版；回收站恢复也带日志行的
  `locale`。只有不知道版本时（旧缓存行、旧队列行）才退回当前内容语言，这与本次改动之前的
  行为一致。
- **浏览**：“我的文章”可以切到“全部语言版本”，每格带语言角标（中文 / English /
  繁體中文）。没拿到 `meta.locales` 时页面明说“这套部署只能列出当前语言”，不把单语言
  结果说成完整档案。

## 客户端无法单方面保证的部分

- **没有“列出某篇作品的其它语言”的公开接口。** 读者视角看不到“这篇还有英文版”的入口；
  作者只能通过“我的文章 → 全部语言版本”找到其它译文。需要服务端补读接口才能做。
- **没有跨语言总数，也没有跨语言分页。** `limit` 按语言计，客户端每种语言只取 50 条；超过
  时列表可能不完整，且接口不提供“还有更多”的信号。
- **跨语言回收站未接入。** 回收站仍按当前内容语言读取；旧语言墓碑要先切内容语言才看得到。
- **`zh-TW` 不是界面语言。** 该版译文可以被列出、编辑，但应用没有繁体中文界面。
- **旧部署。** 忽略 `allLocales`、或根本没有 `/me/articles` 的部署分别落到“只能列当前
  语言”和公开作者列表；两者都不会被说成完整档案。
- **服务端不提供条件更新。** 两个设备同时保存同一版译文时后写覆盖先写，客户端无法阻止。
